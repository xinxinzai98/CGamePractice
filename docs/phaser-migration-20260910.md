# Phaser 架构迁移 · 2026-09-10

用户已批准按架构方案迁移。当前交付为 v0.2，完成主要客户端流程与共享规则 / 存档基础迁移，未做公网部署。

## 实际变更

- 客户端：Phaser 4.2.1，TypeScript、React、Vite。Phaser拥有Boot资源加载、背景与战斗Scene；React负责表单、档案、准备与HUD，服务器仍判定联机战斗。
- 统一逻辑1600×900。Phaser与React覆盖层共用缩放比例，在任意浏览器长宽比下留边，不将画面拉伸。
- 场景流程：主视觉封面 → 登录 / 注册 → 真实加载反馈 → 机库 → 战前准备 → 战斗 / 练习 → 结算 → 准备。
- `packages/simulation` 为strict TypeScript共享模块，输出CommonJS给服务器，客户端直接引用TypeScript源。保留原有规则、随机种子、技能与关卡行为。
- SQLite使用事务、WAL、独立奖励账本；支持旧JSON一次性非覆盖导入。原JSON不删除。
- 准备与结算：房主选任务、难度，双方选角色与配置；结算保存失败每秒重试，逐玩家确认，不重复奖励。收到 `rewardsSaved` 后才显示“已保存”和允许推进。
- 输入：方向键移动，左手技能 / 弹种；按下事件进入队列，防止同帧down/up被渲染循环吞掉，离开或失焦清队列。
- 素材：统一图标图集，原作教学素材、新机甲 / 敌人 / 地形 / Boss；新角色显示尺寸增大但碰撞尺寸保持规则。

## 验证

环境：Node.js 22.22.3。

- `npm run build` 通过：共享规则编译、客户端严格类型检查、Vite生产构建。
- `npm test` **73项通过**：旧规则测试、TypeScript与原型确定性对照、12关数据、Boss与角色协作、房间与准备、账户、SQLite导入、回滚、重复结算及失败重试。
- 实际浏览器使用单独临时SQLite档案和测试服务器，与正式本地个人档案隔离。测试档案人为预设熟练度与金币用于操作验证，不是真实战斗获得的数据。
- 已走通主视觉点击、登录、加载过渡、动态看板、技能点亮与保存。
- 教学场景为旧作Round 1；点击治疗实测HP70→90，同步能量100→85；短方向输入产生移动距离；Esc暂停及返回大厅正常。
- 两个独立登录会话完成创建/加入房间、选择1-3 Boss与难度、双方准备、Phaser新素材战场、全队暂停/继续。
- 两端实际失败结算一致，档案保存成功，返回准备后双方ready清除、关卡保留。胜利与奖励、重连、故障恢复由自动化集成测试验证。
- 控制台在已检查流程中无错误。截图检查确认封面和界面16:9留边、技能树与HUD可见，调整过看板头部裁切。

## 尚需后续打磨

- 尚未逐个人工通关十二关；难度、地图密度、Boss节奏仍需试玩反馈。
- 看板为单图分区网格动画适配，已进入独立组件；不是专业Live2D分层模型。完整Live2D需准备分层与绑定资产。
- 新机甲图集是斜俯视四方向，原始美术仍需继续统一；帧动画、音色、镜头、打击感不是最终品质。
- 关卡解谜当前是角色分工的顺序节点，没有实体闸门，未宣称已实现复杂机关关卡。
- 服务端在此次保留JavaScript协议层；共享规则与客户端已迁移TypeScript，后续可继续迁移协议层。
- SQLite的Node22运行时会显示experimental提示；当前版本已验证，部署时固定Node版本并按实际环境验证。
- 未公网部署、未做异地高延迟或跨操作系统完整人工验收。

## 保留与边界

`NewTank/`、`Chartlet/`未改。`web/`保留原型与原始/新增素材，正式入口为构建后的`client/dist`。迁移前web/server/package源码另存到了工作目录备份，未包含玩家档案。

个人SQLite及旧JSON均在`data/`，被Git忽略；测试账号与测试数据库未作为游戏内容提交。运行和开发命令见README。
