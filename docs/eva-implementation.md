# EVA v3.1 本地实现与验收

日期：2026-09-10。应用版本 `0.3.1`，规则版本 `eva-3.1-local.1`，数据库／档案／内容存储版本为 2。依据 [v3.1 设计](eva-progression-design.md)实施；原始 `NewTank/`、`Chartlet/` 和旧 `web/` 原型未修改。

## 已实现的流程

| 范围 | 当前实现 |
| --- | --- |
| 身份与培养 | 四机体、四驾驶员、三支援成员；账号、参战实体及配置分离。四份培养数据、有效贡献评分、永久研究、免费预设、经费晋阶、等级容量、熟练度、共鸣和有限精通。 |
| 内容 | 183 个首批节点及 3 个旧档能力保留节点；3 主武器、2 近战、9 普通装备、4 精通装备、3 类弹药、3 类消耗品、普通和资历外观。 |
| 合作与任务 | 交叉火力、屏障掩护、三部位 Boss；十二战役小关及独立突袭、护送、防守、供能实验。机体类型有不同动作、资源和协作效果。 |
| MAGI 与复盘 | 未拥有内容试用、同条件 A/B、固定行为模拟队友、双人演习、单阶段复习；事件来源、实际难度、种子与指标可追溯。无正式收益和库存损伤。 |
| 常规经济 | 七类普通补给、联合保底、重复物转调拨凭证、定向兑换、永久所有权与数量库存、预留／消费／返还、带伤出战、维修、自动整备和经费恢复任务。 |
| 特务补给 | 人工收款记录、单次券发行／补发／撤销／核销、常驻商品及许可续期；订单、券、配额同事务。没有接入第三方支付或真实现金价格。 |
| 客户端 | 固定 1600×900；独立机体／成员选择、研究图、配装冲突与容量、物资费用、战术 HUD、账目、资历与档案；新增角色图片、四型战斗资源与可见外观。 |

新接口位于 `/api/eva`，包括研究、晋阶、预设、购买、抽取、调拨、维修、设置和核销；`/api/eva/ledger` 与 `/api/eva/review` 读取当前账号的流水和复盘。房间使用协议 v3；旧经济接口和旧房间协议默认拒绝，旧兼容入口仅由回归测试显式启用。

同一局开战时冻结配置与权益，双方物资在同一事务预留。每秒和实际物资使用变化时保存检查点；数据库写入失败暂停战斗，手动暂停按钮不能绕过。终局先持久登记，双方奖励与返还原子提交；移除房间后仍补发，正常关服也保存待处理终局。进程重启不会恢复正在进行的物理战斗，而是按最后确认的记录中断结算。

## 已完成的验证

- 完整 `npm run build` 通过，共享规则及客户端严格类型检查、Vite 生产构建成功。
- 完整 `npm test` **248 项通过，0 失败、0 跳过**。包含原回归、新域／经济、客户端请求隔离、真实 HTTP／WebSocket、SQLite 故障与并发核销。
- 48 种基础编组通过配置和模拟验证；10 种类型组合使用初始一级、无装备配置，以正常控制输入完成普通难度三阶段 Boss，全部存活，样本耗时 41.05–45.05 秒。未通过修改 Actor、HP 或地图完成通关。
- 验证两条路线永久学习、免费换配、晋阶资格／实际等级、成员和装备效果差异、旧能力迁移、许可取整、熟练度不受许可放大、挂机不自动获贡献、救援按次数计量。
- 验证第二账号结算失败整笔回滚、重启恢复、检查点不可倒退、物资不足双账号预留回滚、同券两个 SQLite 连接竞争仅一次入账，以及关房后紧接关服的终局保存。
- 两个独立浏览器账号使用同型号／同驾驶员进入同局，实际移动并打开双人闸门；其中一人消费 5 发精确弹和 1 件同步电池，另一人消费为 0，持久记录分别对应正确实体。手动检查局最终战败并保存，没有把它记作人工通关。
- 浏览器检查封面、登录、机库、研究、未拥有内容 MAGI、技能能耗和冷却、三部位、暂停、复盘、交易流水、A/B 方案保留及外观表现。资源构建期间曾触发明确的 503 加载失败提示，重试成功；没有将失败视为资源就绪。
- MAGI 目标方案可在真实所有权、研究和容量满足后转为正式预设；新建演习房间的所选试配、种子与难度均传入服务器真实开局，并有网络回归覆盖。

浏览器截图保留在 `output/playwright/`，本次构建／全量测试、演练和迁移验证记录保留在 `work/eva-playtest/`；包含测试账号的目录已加入 Git 忽略。
