# 架构完整性修复 · 2026-09-10

这次修复针对架构审计发现的跨系统不一致：同账号重复领奖、准备配置失效、短按丢失、半局结算、刷新断局、资源假就绪和出生点自动解谜。保留 Phaser / React / 共享 TypeScript 模拟 / Node.js / SQLite，原始 `NewTank/`、`Chartlet/` 和旧 `web/` 源码未改。

## 验证

- `npm run build` 包括共享规则编译、客户端严格类型检查和 Vite 生产构建。
- 全量自动化 164 项：原有规则、迁移、网络、客户端协议，加上故障恢复、交易核实、资源失败、会话竞态、维护工具和新关卡回归。
- 模拟 80/150 ms RTT 与抖动，真实 `RoomClient` 对接真实服务器：短按治疗、暂停和同局恢复通过。短按射击与连续空包恰好产生一发，未放宽运行时输入有效期。
- 结算故障测试显式保持数据库故障，验证两名玩家均未收奖，再解除故障检查同进程补发；另覆盖重启恢复、重复登记与重复请求。
- 四场 Boss 以正常双人输入通关，所有阶段均经历再次协作开盾；最后一场包含倒地救援。1-3 额外覆盖轻松/标准/困难。该验证证明可通关，不代表真人难度和平衡已最终定稿。
- 真实 Phaser 资源页验证：封面 404 不触发 ready；Boss 图缺失拒绝就绪；恢复后只补加载失败资源。测试页为 `client/tests/assets-browser.html`。
- 浏览器隔离档案验证：抽奖服务器完成后故意丢弃响应，点击“重试核实”后补给券只从 10 变成 9；准备后点亮并保存“坚韧装甲”，席位回到“正在配置”。
- 两个独立浏览器身份进入同一 1-3 战斗；一方刷新后回到原角色和正在进行的战斗，可以继续暂停。战斗目标、实体闸门、阶段条和 16:9 画面已截图检查；最终页面流程无意外控制台错误。
- 本地玩家库先一致备份，再将备份恢复到独立库并迁移，核对完整档案和账号凭据不变、两个既有测试账号登录成功；正式本地库升级后再次比对一致。

完整测试采用两 worker，避免同时启动大量 SQLite/网络测试进程。网络测试使用明确故障解除时点和持续输入，不依赖偶然的事件循环时序。

## 资源与内容边界

启动只预载封面图，约 2.56 MiB；原来 Boot 一次预载约 23.60 MiB。后续按需加载有共享素材，不能把各包大小直接相加作为首次下载量。生产复制 38 张引用图片，约 34.31 MiB；未删除原素材。

四个 Boss 的机制定义已分开，仍复用 `boss-core` 美术。看板仍是单图网格适配；自然分层角色动画、角色招募、装扮库存和新增机体是后续内容/养成扩展，没有在本次伪装成已完成的成品。

## 运行和恢复边界

运行手册见 [multiplayer.md](multiplayer.md)。代码与玩家库分开维护；真实账号、数据库和补给测试密码不提交。

刷新恢复针对页面重载或短暂断网，当前保留窗口为 30 秒。服务器进程重启后需要重新组队，账号与已持久记录的结算保留。数据盘完全不可写时，未登记成功的终局只能暂存在内存；若此时进程又崩溃，无法承诺恢复该未确认记录。界面不会将其标为已保存。

备份使用 SQLite 一致快照，恢复只能写入新目标，不覆盖当前玩家库。部署时仍需按真实服务器配置持久卷、定时备份与 HTTPS；本轮未部署公网。Docker daemon 未运行，镜像构建未执行，不能将本地 Node 验证等同于容器环境验收。
